# 음원 조정 프로그램 페이지별 참고 사이트 및 와이어프레임 구성안

- 작성일: 2026-04-30 14:00 (Asia/Seoul)
- 기준 문서: 음원 조정 프로그램 PRD
- 문서 목적: 페이지별 참고 사이트 정보와 페이지별 와이어프레임 구성안을 한 번에 정리하여, 시안 수집 및 상세 화면 설계에 바로 활용할 수 있도록 한다.

---

## 1. 문서 개요

본 문서는 브라우저 기반 음원 조정 프로그램의 페이지 설계를 위한 참고 자료 정리본이다.

대상 페이지는 아래 5개다.

1. 음원 자르기
2. 음원 분석
3. Key 변환
4. 음량 증폭
5. Stem 분리 및 음량 조절

문서 구성은 아래 두 축으로 나뉜다.

- 페이지별로 참고하기 좋은 사이트 정보
- 페이지별 와이어프레임 구성안

이 문서는 구현용 PRD를 직접 대체하는 문서가 아니라, **디자인 시안 확보와 화면 구조 설계**를 위한 보조 문서로 사용한다.

---

## 2. 전체 디자인 방향 요약

이 프로그램은 전문 DAW처럼 복잡하게 보이기보다, **초보자도 바로 이해할 수 있는 툴형 UI**로 설계하는 것이 적합하다.

핵심 방향은 아래와 같다.

- 공통 레이아웃은 통일
- 페이지마다 핵심 기능이 한눈에 보이도록 구성
- 업로드 → 조작 → 결과 확인 → 다운로드 흐름을 명확하게 유지
- 파형 중심 페이지와 결과 카드 중심 페이지를 구분
- 복잡한 기능은 단계적으로 노출
- 원본과 결과를 시각적으로 명확히 분리

권장 톤앤매너는 아래와 같다.

- 1페이지, 4페이지: 파형 중심 편집형
- 2페이지, 3페이지: 결과 카드 중심 툴형
- 5페이지: 채널 카드 중심 믹서형

---

## 3. 페이지별 참고 사이트 정보

## 3.1 전체 참고 사이트 5개 요약

### 1) Moises
가장 우선적으로 참고할 사이트다.

적합한 이유:
- Key / BPM 분석 흐름 참고에 적합
- 반음 단위 key 변경 UI 참고에 적합
- stem 분리 및 stem별 제어 UI 참고에 적합
- 결과 카드 구조와 트랙 제어 방식이 직관적임

주로 참고할 페이지:
- 2페이지 음원 분석
- 3페이지 Key 변환
- 5페이지 Stem 분리 및 음량 조절

참고 포인트:
- 업로드 후 결과 정보 노출 방식
- Key / BPM 카드 표현 방식
- semitone 조절 UX
- stem별 볼륨/재생/다운로드 구조

---

### 2) AudioMass
브라우저 기반 파형 편집 화면 참고용으로 매우 적합하다.

적합한 이유:
- waveform 중심 화면 구조가 명확함
- cut / trim / volume 편집 흐름 참고에 적합
- 복잡한 멀티트랙 구조 없이 단일 오디오 편집 UX를 참고하기 좋음

주로 참고할 페이지:
- 1페이지 음원 자르기
- 4페이지 음량 증폭

참고 포인트:
- 중앙 대형 waveform 배치
- 최소한의 편집 도구 구성
- 파형 아래 또는 주변의 컨트롤 배치
- 단일 오디오 편집 툴의 화면 밀도

---

### 3) BandLab
전체적인 작업실형 앱 구조와 믹서 감각을 참고하기 좋다.

적합한 이유:
- 트랙/믹서형 화면 배치 참고 가능
- 좌측 네비게이션 + 중앙 작업영역 + 우측/하단 제어 영역 구조 참고 가능
- 볼륨 조절 UI와 채널 분리 UI를 설계할 때 도움됨

주로 참고할 페이지:
- 공통 앱 구조
- 4페이지 음량 증폭
- 5페이지 Stem 분리 및 음량 조절

참고 포인트:
- 작업 툴형 레이아웃
- 볼륨 슬라이더/패널 구조
- 멀티채널을 동시에 보여주는 방식
- 정보 밀도를 높이되 가독성을 유지하는 방식

---

### 4) LALAL.AI
stem 분리 기능의 상태 흐름 참고에 특히 적합하다.

적합한 이유:
- 업로드 → 분리 실행 → 미리듣기 → 다운로드 흐름이 명확함
- 처리 중 상태와 결과 상태 구성이 깔끔함
- stem 분리 기능만 별도로 단순하게 보여주는 방식 참고 가능

주로 참고할 페이지:
- 5페이지 Stem 분리 및 음량 조절

참고 포인트:
- 파일 업로드 후 진행 상태 노출 방식
- 분리 전/분리 중/분리 완료 상태 구분
- preview와 full processing 구분 방식
- 결과 다운로드 흐름 정리 방식

---

### 5) Descript
trim/split 편집 흐름의 직관성을 참고하기 좋다.

적합한 이유:
- 편집 동작을 어렵지 않게 풀어내는 UX 감각이 좋음
- 복잡한 오디오 편집 기능도 친숙한 인터페이스로 정리하는 방식 참고 가능
- 선택, 분할, 컷 작업의 사용자 이해도를 높이는 구조를 참고할 수 있음

주로 참고할 페이지:
- 1페이지 음원 자르기

참고 포인트:
- split/trim 작업의 사용자 행동 흐름
- 편집 기능 라벨링
- 결과를 직관적으로 이해하게 만드는 인터랙션
- 초보자 친화적인 편집 UI 구성

## 3.2 페이지별 사이트 매칭

## 1페이지: 음원 자르기

### 우선 참고 사이트
1. AudioMass
2. Descript

### 참고 이유
이 페이지는 파형이 중심이 되어야 하므로, waveform이 넓고 명확하게 보이는 사이트가 적합하다.
AudioMass는 단일 음원 편집 화면 구성 참고에 강하고, Descript는 split/trim 조작의 직관적인 흐름을 설계할 때 도움이 된다.

### 가져올 요소
- 넓은 waveform 중심 레이아웃
- 시작점/종료점 핸들 또는 선택 영역 구조
- 재생/정지/자르기 버튼의 단순한 배치
- 선택 구간 길이 표시 영역
- 편집 결과 확인 후 다운로드하는 흐름

---

## 2페이지: 음원 분석

### 우선 참고 사이트
1. Moises

### 참고 이유
이 페이지는 편집보다 결과 확인이 핵심이므로, 분석 결과 카드가 명확하게 보이는 구조가 적합하다.
Moises는 업로드 후 key, bpm 등 핵심 정보를 빠르게 보여주는 흐름이 잘 정리되어 있다.

### 가져올 요소
- 결과 카드형 UI
- Key / BPM 값을 크게 보여주는 방식
- 분석 버튼과 결과 영역의 우선순위 분리
- 참고용 안내 문구 배치 방식

---

## 3페이지: Key 변환

### 우선 참고 사이트
1. Moises

### 참고 이유
이 페이지는 semitone 조절이 핵심 기능이므로, 키 변화 값을 사용자에게 단순하고 명확하게 보여주는 UI가 중요하다.
Moises는 1 semitone 단위 조절 UX를 참고하기 가장 적합하다.

### 가져올 요소
- - / + 기반 semitone 조절 UI 또는 슬라이더
- 현재 Key와 예상 변환 Key를 함께 보여주는 정보 구조
- 원본 재생 / 결과 재생 / 다운로드 흐름
- Reset 또는 기본값 복귀 버튼

---

## 4페이지: 음량 증폭

### 우선 참고 사이트
1. AudioMass
2. BandLab

### 참고 이유
이 페이지는 파형 기반 단일 파일 조절이 기본이므로 AudioMass의 단일 편집 화면 구성이 유용하다.
동시에 gain 제어, 볼륨 조절 같은 컨트롤은 BandLab의 믹서 감각을 참고하면 더 직관적인 조절 UI를 만들 수 있다.

### 가져올 요소
- waveform 중심 화면
- gain 슬라이더
- 현재 적용값 숫자 표시
- clipping 방지 옵션 토글
- 결과 미리듣기 및 적용 버튼 구조

---

## 5페이지: Stem 분리 및 음량 조절

### 우선 참고 사이트
1. LALAL.AI
2. Moises
3. BandLab

### 참고 이유
이 페이지는 가장 복잡하다.
LALAL.AI는 처리 상태 흐름 설계에 유리하고, Moises는 stem 결과 화면과 제어 패널 참고에 강하며, BandLab은 멀티채널/믹서형 UI 설계에 도움된다.

### 가져올 요소
- 업로드 → 분리 실행 → 결과 확인 흐름
- stem별 카드 또는 세로 패널 구조
- 개별 stem 재생 버튼
- 개별 볼륨 슬라이더
- mixed 재생 / mixed 다운로드
- 진행 상태 표시 방식

## 5. 페이지별 와이어프레임 구성안

## 5.1 1페이지 — 음원 자르기

### 목적
사용자가 mp3를 업로드한 뒤 원하는 구간만 선택하여 잘라내고 다운로드할 수 있도록 한다.

### 화면 구성

#### A. 페이지 헤더
- 제목: 음원 자르기
- 설명: 원하는 구간만 선택하여 잘라낼 수 있습니다.

#### B. 파일 업로드 카드
- 드래그 앤 드롭 영역
- 파일 선택 버튼
- 업로드 후 파일명 / 길이 / 용량 표시

#### C. 중앙 파형 카드
- waveform 표시
- 시작 바
- 종료 바
- 현재 재생 위치 표시선
- 선택 영역 강조 표시

#### D. 구간 정보 카드
- 시작 시점
- 종료 시점
- 선택 길이
- 현재 선택 상태 문구

#### E. 컨트롤 바
- 원본 재생
- 정지
- 시작점 기준 미리듣기
- 종료점 기준 미리듣기
- 자르기 실행

#### F. 결과 카드
- 잘라낸 결과 미리듣기 플레이어
- 다운로드 버튼
- 결과 파일명 예시 표시

#### G. 오류 / 가이드 카드
- 시작점은 종료점보다 앞서야 합니다.
- 너무 짧은 구간은 품질이 떨어질 수 있습니다.

### 텍스트 와이어프레임
```text
[헤더]
음원 자르기
원하는 구간만 선택하여 잘라낼 수 있습니다.

[업로드 카드]
[ 파일 드래그 앤 드롭 / 파일 선택 ]

[파일 정보]
파일명 | 길이 | 용량

[파형 카드]
---------------------------------------------------
|                                                 |
|                 Waveform Viewer                 |
|    |<-- 시작 핸들 ------ 선택 구간 ------ 종료 핸들 -->|
|                                                 |
---------------------------------------------------

[구간 정보 카드]
시작 시점 | 종료 시점 | 선택 길이

[컨트롤 바]
[원본 재생] [정지] [시작점 미리듣기] [종료점 미리듣기] [자르기]

[결과 카드]
결과 미리듣기 플레이어
[다운로드]

[안내/오류]
오류 또는 가이드 문구
```

### 핵심 우선순위
- 파형이 가장 크게 보여야 함
- 시작/종료 선택 UI가 명확해야 함
- 자르기 버튼의 위치가 직관적이어야 함
- 결과 확인과 다운로드가 바로 이어져야 함

## 5.2 2페이지 — 음원 분석

### 목적
업로드한 음원의 Key / BPM 추정 결과를 빠르게 확인하도록 한다.

### 화면 구성

#### A. 페이지 헤더
- 제목: 음원 분석
- 설명: 업로드한 음원의 Key와 BPM을 참고용으로 분석합니다.

#### B. 파일 업로드 카드
- 드래그 앤 드롭
- 파일 선택 버튼
- 업로드 후 파일 정보 표시

#### C. 실행 카드
- 원본 재생 버튼
- 분석 실행 버튼
- 분석 중 상태 표시

#### D. 결과 카드 영역
- Key 카드
- BPM 카드
- 참고 안내 카드

#### E. 하단 메시지 카드
- Unknown 처리
- 실패 안내
- 재시도 안내

### 텍스트 와이어프레임
```text
[헤더]
음원 분석
업로드한 음원의 Key와 BPM을 참고용으로 분석합니다.

[업로드 카드]
[ 파일 드래그 앤 드롭 / 파일 선택 ]

[파일 정보]
파일명 | 길이 | 용량

[실행 카드]
[원본 재생] [분석 실행]

[결과 카드 영역]
-----------------------------------------------
|   Key 카드   |    BPM 카드    | 안내 카드   |
|  A minor     |    128 BPM     | 참고용 추정 |
-----------------------------------------------

[상태/오류]
분석 상태 또는 오류 메시지
```

### 핵심 우선순위
- 분석 버튼이 명확해야 함
- 결과 값은 크게 보여야 함
- 결과 카드가 화면의 중심이 되어야 함
- 분석 결과가 참고용이라는 점이 분명해야 함

---

## 5.3 3페이지 — Key 변환

### 목적
반음 단위로 key를 조절하고, 결과를 재생/다운로드할 수 있도록 한다.

### 화면 구성

#### A. 페이지 헤더
- 제목: Key 변환
- 설명: 반음 단위로 키를 조절하고 결과를 저장할 수 있습니다.

#### B. 파일 업로드 카드
- 파일 업로드
- 파일 정보 표시

#### C. 원본 정보 카드
- 추정 Key
- 추정 BPM
- 원본 재생 버튼

#### D. Key 조절 카드
- -12 ~ +12 semitone 조절 UI
- 슬라이더 또는 - / + 버튼
- 현재 semitone 값 표시

#### E. 예상 결과 카드
- 원본 Key
- 변환 후 예상 Key
- 템포 유지 안내

#### F. 실행 / 결과 카드
- 변환 실행
- 결과 재생
- 다운로드

#### G. 안내 카드
- Unknown이어도 변환 가능
- 템포 유지됨

### 텍스트 와이어프레임
```text
[헤더]
Key 변환
반음 단위로 키를 조절하고 결과를 저장할 수 있습니다.

[업로드 카드]
[ 파일 드래그 앤 드롭 / 파일 선택 ]

[원본 정보 카드]
원본 Key | 원본 BPM | [원본 재생]

[Key 조절 카드]
---------------------------------------
|   [-]   +3 semitone   [+]           |
|   또는 슬라이더 (-12 ~ +12)         |
---------------------------------------

[예상 결과 카드]
원본 Key: A minor
변환 후 예상 Key: C minor
템포: 유지

[실행/결과 카드]
[변환 실행] [결과 재생] [다운로드]

[안내/오류]
가이드 문구 / 오류 메시지
```

### 핵심 우선순위
- semitone 조절 UI가 핵심이어야 함
- 예상 Key가 바로 보이도록 해야 함
- 원본/결과 비교 흐름이 분명해야 함
- 변환 버튼과 결과 버튼이 구분되어야 함

---

## 5.4 4페이지 — 음량 증폭

### 목적
gain을 조절하며 결과를 확인하고 최종 파일을 저장하도록 한다.

### 화면 구성

#### A. 페이지 헤더
- 제목: 음량 증폭
- 설명: 음량을 키우거나 줄여 결과를 확인하고 저장할 수 있습니다.

#### B. 파일 업로드 카드
- 파일 업로드
- 파일 정보

#### C. 파형 카드
- waveform 표시
- 현재 재생 위치 표시

#### D. 조절 패널
- gain 슬라이더
- 숫자 입력 또는 현재 적용값 표시
- clipping 방지 토글

#### E. 실행 / 미리듣기 카드
- 원본 재생
- 결과 미리듣기
- 적용
- 다운로드

#### F. 안내 카드
- 과도한 증폭은 음질 저하 유발 가능
- clipping 방지 on/off 설명

### 텍스트 와이어프레임
```text
[헤더]
음량 증폭
음량을 키우거나 줄여 결과를 확인하고 저장할 수 있습니다.

[업로드 카드]
[ 파일 드래그 앤 드롭 / 파일 선택 ]

[파형 카드]
---------------------------------------------------
|                    Waveform                      |
---------------------------------------------------

[조절 패널]
Gain: [+4.5 dB]
[--------- 슬라이더 ---------]
[ ] clipping 방지

[컨트롤 바]
[원본 재생] [결과 미리듣기] [적용] [다운로드]

[가이드/오류]
안내 문구 / 오류 메시지
```

### 핵심 우선순위
- 파형과 gain 슬라이더가 핵심
- 현재 적용값이 명확해야 함
- clipping 방지 옵션이 분리되어 보여야 함
- 결과 확인과 다운로드 흐름이 자연스러워야 함

---

## 5.5 5페이지 — Stem 분리 및 음량 조절

### 목적
음원을 4개 stem으로 분리하고, 각 stem의 음량을 조절한 뒤 mixed 결과를 재생/다운로드하도록 한다.

### 화면 구성

#### A. 페이지 헤더
- 제목: Stem 분리 및 음량 조절
- 설명: 음원을 4개 stem으로 분리하고 각 파트를 조절할 수 있습니다.

#### B. 업로드 및 실행 카드
- 파일 업로드
- 파일 정보
- 분리 실행 버튼
- 진행 상태 표시

#### C. Stem 카드 영역
4개 카드 또는 4열 구조 권장
- Drums
- Bass
- Vocals
- Other

각 카드 포함 요소:
- stem 이름
- 재생 버튼
- 볼륨 슬라이더
- 현재 볼륨 값
- 다운로드 버튼

#### D. 전체 Mix 카드
- 전체 mix 재생
- mixed 다운로드
- 현재 mix 요약 정보

#### E. 가이드 / 오류 카드
- stem 분리 품질은 곡 특성에 따라 달라질 수 있습니다.
- 실시간 반영 지연 가능

### 텍스트 와이어프레임
```text
[헤더]
Stem 분리 및 음량 조절
음원을 4개 stem으로 분리하고 각 파트를 조절할 수 있습니다.

[업로드 카드]
[ 파일 드래그 앤 드롭 / 파일 선택 ]
[분리 실행]

[진행 상태]
Stem 분리 중... 45%

[Stem 카드 영역]
---------------------------------------------------------------
| Drums  | Bass   | Vocals | Other                            |
| [재생] | [재생] | [재생] | [재생]                           |
| 슬라이더| 슬라이더| 슬라이더| 슬라이더                        |
| +2 dB  | -1 dB  | +3 dB  | 0 dB                            |
|[다운로드]|[다운로드]|[다운로드]|[다운로드]                    |
---------------------------------------------------------------

[전체 Mix 카드]
[전체 Mix 재생] [Mixed 다운로드]

[가이드/오류]
안내 문구 / 오류 메시지
```

### 핵심 우선순위
- 분리 실행과 진행 상태가 분명해야 함
- 4개 stem 패널 구조가 명확해야 함
- 개별 stem 조절과 mixed 결과 흐름이 분리되어야 함
- 최종 다운로드 동선이 쉬워야 함

## 6. 상태별 화면 설계 가이드

각 페이지는 최소 아래 5가지 상태를 별도 시안으로 확보하는 것이 좋다.

### 1) 초기 상태
- 파일 미업로드
- 핵심 실행 버튼 비활성화
- 업로드 유도 문구 노출

### 2) 업로드 완료 상태
- 파일명 / 길이 / 용량 표시

### 3) 처리 중 상태
- 스피너 또는 진행률 바
- 버튼 일부 비활성화
- 처리 중 안내 문구

### 4) 처리 완료 상태
- 결과 재생 가능
- 다운로드 버튼 활성화
- 성공 메시지 표시

### 5) 오류 상태
- 오류 원인 안내
- 재시도 버튼 또는 재업로드 유도
- 기술적인 설명보다 이해 쉬운 문구 사용

## 9. 최종 정리

이 프로그램의 화면 설계는 아래 방향으로 가는 것이 가장 적합하다.

- 너무 전문가용처럼 복잡하지 않게
- 파형 중심 / 결과 카드 중심 / 채널 카드 중심 구조를 상황별로 구분
- 업로드 → 조작 → 결과 → 다운로드 흐름을 명확히 유지
- 공통 레이아웃은 통일하고, 페이지별 핵심 기능만 전면에 배치
- 디자인 시안은 페이지별로 초기 / 업로드 완료 / 처리 중 / 완료 / 오류 상태까지 함께 준비

즉, 실전 시안 제작 시에는 아래 조합을 기준으로 진행하면 된다.

- 공통 구조: BandLab 감각 참고
- 파형 편집 화면: AudioMass 참고
- 분석 / Key 변환: Moises 참고
- Stem 분리 상태 흐름: LALAL.AI 참고
- trim/split UX 감각: Descript 참고

이 기준으로 시안을 만들면, PRD의 기능 요구사항을 무리 없이 반영하면서도 일관된 제품 느낌을 유지할 수 있다.
