- 작성일: 2026-04-30
- 문서 목적:

- 적용 대상:

## 1. 권장 제작 플로우

기존 아이디어 자체는 매우 좋다. 다만 `이미지 → 이미지 → 코드`만으로 넘기면 구현 단계에서 정보 손실이 생기므로, 각 단계 사이에 **구조화된 명세 문서**를 반드시 넣는 것을 권장한다.

### 권장 최종 플로우

1. PRD 확정
2. 사용자 선호 레퍼런스 PNG 수집
3. 페이지별 디자인 브리프 작성
4. GPT Image 2.0으로 페이지 예시 PNG 생성
5. Claude Design에 PRD + 브리프 + 예시 PNG + 상태 명세 전달
6. Claude Design에서 상세 시안/코드 초안 생성
7. 구현용 handoff 문서 생성
8. Codex 또는 Claude Code로 실제 페이지 구현
9. 페이지별 테스트 후 다음 페이지 진행

### 핵심 원칙

- PNG는 **방향성 시안**으로 본다.
- 최종 구현 기준은 **명세 문서**로 잡는다.
- 각 페이지는 반드시 **상태(state)** 까지 정의한다.
- 1페이지부터 차례대로 진행하되, 각 페이지는 **디자인 시안 승인 후 구현**한다.
- 페이지 구현 전 공통 디자인 토큰과 공통 컴포넌트 기준을 먼저 고정한다.

## 3. 공통 디자인 원칙

이 프로젝트의 UI는 “일반적인 예쁜 웹앱”보다는 **오디오 작업 도구**에 가깝다. 따라서 아래 기준을 권장한다.

### 3.1 전체 방향

- 데스크톱 작업 도구 느낌
- 조작 대상(파형, 슬라이더, 재생 상태)이 분명히 보여야 함
- 정보가 많아도 한눈에 읽히게 구성
- 과도한 장식보다 기능 가독성 우선
- 다크 테마 우선 검토 권장  
  (파형, 마커, 재생 헤드, 선택 구간, stem 레벨 표시가 더 잘 보임)

### 3.2 정보 구조 원칙

- 상단: 페이지 제목 + 설명 + 업로드 상태
- 본문 중심: 핵심 작업 영역
- 우측 또는 하단: 설정/결과/다운로드
- 중요한 액션: 항상 고정 위치 유지
- 플레이어, 분석 결과, 다운로드는 시선 이동이 적게 배치

### 3.3 공통 상태

모든 페이지는 가능하면 아래 상태를 정의한다.

- empty: 업로드 전
- uploaded: 파일 업로드 후
- processing: 분석/변환/분리 중
- success: 결과 생성 완료
- error: 오류 발생
- downloading: 다운로드 준비 중 (필요 시)

### 3.4 공통 컴포넌트

- 파일 업로드 박스
- 파일 메타 정보 카드
- 오디오 플레이어
- 파형 뷰어
- 구간 선택 바
- 슬라이더
- 수치 입력/표시
- 분석 결과 카드
- 상태 배지
- 다운로드 버튼
- 경고/오류 메시지 박스
- 진행 상태 표시 영역

### 3.5 공통 디자인 토큰 예시

- Primary: 블루 또는 블루그린 계열
- Success: 그린
- Warning: 옐로/오렌지
- Error: 레드
- Waveform base: 중간 명도
- Selection range: Primary 계열 반투명
- Playhead: 대비 높은 강조색
- Border radius: 10~16px
- Panel/card: 은은한 대비, 과도한 그림자 지양
- Font scale:
  - Page title
  - Section title
  - Body
  - Caption
  - Meta label
- Spacing scale:
  - 8 / 12 / 16 / 24 / 32

## 5. 페이지별 핵심 브리프 초안

아래는 바로 활용하기 쉬운 초기 초안이다.

### 5.1 1페이지 음원 자르기

- 목적: 업로드한 mp3의 원하는 구간을 직관적으로 선택하고 잘라서 다운로드
- 핵심 컴포넌트:
  - 업로드 박스
  - 전체 파형 뷰어
  - 좌측 바 / 우측 바
  - 현재 선택 구간 표시
  - 재생 컨트롤
  - 자르기 실행 버튼
  - 다운로드 버튼
- 중요 동작:
  - 좌측 바: 해당 위치부터 계속 재생
  - 우측 바: 해당 위치 5초 전부터 미리듣기
  - 잘라낸 결과 확인 후 다운로드
- 파일명 규칙:
  - `원본음원명+(cut).mp3`

### 5.2 2페이지 음원 분석

- 목적: 업로드한 mp3의 Key, BPM을 참고용으로 빠르게 확인
- 핵심 컴포넌트:
  - 업로드 박스
  - 파일 메타 카드
  - 전체 재생 플레이어
  - 분석 실행 버튼
  - 결과 카드(Key, BPM)
  - 추정값 안내 문구
- 중요 동작:
  - 업로드 후 전체 재생 가능
  - 분석 중 로딩 상태 명확히 표시
- 안내 문구:
  - `추정값이며 실제 조성/템포와 다를 수 있습니다.`

### 5.3 3페이지 Key 변환

- 목적: 템포 유지 상태로 ±12 semitone 범위 내 Key 변환 및 다운로드
- 핵심 컴포넌트:
  - 업로드 박스
  - 원본 정보 카드(Key, BPM)
  - semitone 조절 컨트롤
  - 변환 전/후 정보 표시
  - 전체 재생 플레이어
  - 변환 실행 / 다운로드 버튼
- 중요 동작:
  - 업로드 시 원본 Key/BPM 표시
  - 변환 결과 미리듣기
  - 변환된 Key 기준 파일명 생성
- UI Key 표기 권장:
  - `G Major`, `A minor`, `F# minor`, `Bb Major`
- 파일명 표기 권장:
  - `G_Major`
  - `A_minor`
  - `F_sharp_minor`
  - `B_flat_Major`

### 5.4 4페이지 음량 증폭

- 목적: 파형을 보며 gain을 조절하고 clipping 방지 옵션을 적용해 결과 다운로드
- 핵심 컴포넌트:
  - 업로드 박스
  - 파형 뷰어
  - gain 슬라이더
  - clipping 방지 토글
  - 실시간 재생 영역
  - 결과 다운로드 버튼
- 중요 동작:
  - gain 조절 시 즉시 청감 확인 가능
  - 결과 파일명:
    - `원본음원명+(amp).mp3`

### 5.5 5페이지 스템 분리 및 믹스

- 목적: 드럼/베이스/보컬/기타 4채널로 분리하고, 각 stem의 음량을 조절하여 mixed 결과까지 다운로드
- 핵심 컴포넌트:
  - 업로드 박스
  - 분리 실행 버튼
  - processing 상태 패널
  - 4개 채널 카드
  - 채널별 재생/음량 조절 UI
  - mixed 결과 재생/다운로드
  - stem 개별 다운로드
- 채널:
  - Drum
  - Bass
  - Vocal
  - Other
- 결과물:
  - stem별 mp3
  - mixed mp3
- 파일명 예시:
  - `원본음원명+(drum).mp3`
  - `원본음원명+(bass).mp3`
  - `원본음원명+(vocal).mp3`
  - `원본음원명+(other).mp3`
  - `원본음원명+(mixed).mp3`

## 11. 최종 권장 사항

이 프로젝트에서는 아래 3가지를 꼭 지키는 것을 권장한다.

### 11.1 이미지보다 명세를 우선
PNG는 방향성 참고용으로 매우 유용하지만, 구현 기준은 반드시 md 문서 명세로 잡는다.

### 11.2 상태 정의를 먼저
각 페이지마다 empty / uploaded / processing / success / error를 먼저 정리하면 구현 안정성이 크게 올라간다.

### 11.3 공통 컴포넌트 재사용
5페이지가 서로 달라 보여도 실제로는 공통 UI 요소가 많다.  
업로드 박스, 플레이어, 결과 카드, 다운로드 버튼, 상태 배지 등을 공통화하면 구현 효율이 높아진다.
