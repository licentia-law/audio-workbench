## 0. 전제 및 해석 기준

이 DTL은 아래 PRD 기준을 구현 관점으로 구체화한 문서다.

- 브라우저 UI + 로컬 백엔드 구조
- 입력/출력 모두 mp3만 지원
- 업로드 제한: 10분 이하, 20MB 이하
- 세션 종료 후 히스토리/음원 영구 저장 없음
- 1페이지부터 순차 구현 및 테스트
- 각 페이지 구현 전에 해당 페이지 디자인 시안 선행 확정

## 1. 권장 기술 선택안

본 프로젝트는 개인용 로컬 실행, Windows + Chrome 데스크톱 우선, 오디오 처리 포함이라는 조건상 아래 조합을 기본안으로 권장한다.

### 1.3 Audio Processing
- ffmpeg / ffprobe: 메타데이터, 인코딩, 컷, gain, mp3 출력
- librosa: bpm/key 추정 보조
- soundfile / numpy: 파형 데이터 처리 보조
- Rubber Band CLI 또는 동급 pitch shift 엔진: 템포 유지 key 변환

### 1.4 테스트/품질
- pytest
- httpx (API 테스트)
- Playwright 또는 최소한 수동 시나리오 테스트 문서
- Ruff / Black / mypy (권장)

### 1.5 이유
- React + Tailwind는 Claude Design / Codex / Claude Code 결과물을 흡수하기 쉽다.
- FastAPI는 로컬 백엔드 + 파일 업로드 + 긴 처리 작업 상태 반환 구조에 적합하다.
- ffmpeg 중심으로 컷/증폭/mp3 출력 처리의 안정성을 확보할 수 있다.
- WaveSurfer.js는 1페이지, 4페이지 구현 난도를 크게 낮춘다.

# backend/app/core/filename_policy.py
from pathlib import Path
import re


def sanitize_base_name(filename: str) -> str:
    base = Path(filename).stem
    base = base.strip().replace(" ", "_")
    base = re.sub(r"[^A-Za-z0-9_\-().]", "", base)
    return base or "audio"


def with_suffix(filename: str, suffix: str) -> str:
    base = sanitize_base_name(filename)
    return f"{base}({suffix}).mp3"
```

# backend/app/services/cut_service.py
from pathlib import Path
import subprocess


def cut_mp3(input_path: Path, output_path: Path, start_sec: float, end_sec: float) -> None:
    duration = max(0.0, end_sec - start_sec)
    if duration <= 0:
        raise ValueError("start_sec must be earlier than end_sec")

    cmd = [
        "ffmpeg", "-y",
        "-i", str(input_path),
        "-ss", f"{start_sec:.3f}",
        "-t", f"{duration:.3f}",
        "-codec:a", "libmp3lame",
        str(output_path),
    ]
    subprocess.run(cmd, check=True)
```

KEY_FILENAME_MAP = {
    "F# minor": "F_sharp_minor",
    "Bb Major": "B_flat_Major",
}


def key_result_filename(original_filename: str, key_label: str | None, semitone: int) -> str:
    if key_label and key_label != "Unknown":
        safe = KEY_FILENAME_MAP.get(key_label, key_label.replace(" ", "_"))
        safe = safe.replace("#", "_sharp").replace("b", "_flat")
        return with_suffix(original_filename, safe)
    return with_suffix(original_filename, f"key_shift_{semitone:+d}")
```

# backend/app/services/amplify_service.py
from pathlib import Path
import subprocess


def amplify_mp3(input_path: Path, output_path: Path, gain_db: float, prevent_clipping: bool) -> None:
    audio_filter = f"volume={gain_db}dB"
    if prevent_clipping:
        audio_filter = f"{audio_filter},alimiter=limit=0.95"

    cmd = [
        "ffmpeg", "-y",
        "-i", str(input_path),
        "-af", audio_filter,
        "-codec:a", "libmp3lame",
        str(output_path),
    ]
    subprocess.run(cmd, check=True)
```

## 12. 최종 결론

이 프로젝트의 핵심은 “오디오 처리 기능” 자체보다도, **로컬 환경에서 안정적으로 돌아가는 브라우저 기반 작업 흐름**을 만드는 것이다.

따라서 구현 우선순위는 다음처럼 잡는 것이 가장 안전하다.

- 공통 기반 먼저
- 1페이지부터 차례대로
- 각 페이지는 디자인 시안 승인 후 구현
- 파일명/상태/오류/임시파일 정책은 중앙집중식으로 관리
- 무거운 오디오 처리는 백엔드, 조작과 가시성은 프론트에 집중

이 DTL을 기준으로 작업하면, Claude Design → Codex/Claude Code → 구현/테스트 흐름으로 이어질 때 흔들림이 적고, 각 페이지를 순차적으로 닫아가며 MVP 완성에 도달하기 쉽다.
